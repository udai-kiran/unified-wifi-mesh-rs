# Pinned upstream crypto oracle

`regen` builds a temporary executable from the exact pinned upstream git
objects, a declaration shim, and the fixed inputs in `vectors.cpp`. The
upstream checkout defaults to the sibling `unified-wifi-mesh` directory and
is read only through `git show`; use `--upstream PATH` for a different
checkout. Python 3, git, a C compiler, a C++17 compiler, and OpenSSL 3 headers
and libcrypto are required. The AES-SIV C source and its header are fetched
whole for the temporary build; they are not stored in this repository.

```sh
python3 tools/upstream-crypto-vectors/regen
python3 tools/upstream-crypto-vectors/regen --check
python3 tools/upstream-crypto-vectors/regen --generated-form
python3 -m unittest tools/test_upstream_crypto_vectors.py
```

`--check` rebuilds and compares the entire fixture, including provenance.
Compiler, OpenSSL or provider changes therefore require review of the
regenerated bytes; they are not silently normalized. `--out PATH` selects a
fixture for regeneration or comparison. Generation validates all required
case names and row fields before replacing the output atomically.
`--generated-form` independently generates one key per supported curve,
checks its SPKI subjectPublicKey has uncompressed SEC1 form, and prints the
provider and randomized DER without writing a fixture.

To check a SHA-256/DER connector signature from another implementation, pass
lowercase hexadecimal message bytes, public SPKI DER, and signature DER:

```sh
python3 tools/upstream-crypto-vectors/regen --verify-signature MESSAGE_HEX SPKI_DER_HEX SIGNATURE_DER_HEX
```

It prints `verified=1` and exits 0 for an accepted signature; it prints
`verified=0` and exits 1 for a rejected signature. Errors in invocation,
source access, compilation, or execution exit 2. The checked-in connector
signatures were created once with the extracted signer and are verified with
an imported public key by the extracted verifier on each regeneration.

The TSV columns are category, case, inputs, upstream return value, and output.
Input/output byte strings are lowercase hexadecimal; `-` means an empty byte
string. Named fields use `key=value` separated by semicolons, and comma
separates ordered pieces. Numeric lengths and return values are decimal. The
CBC return value is the upstream returned plaintext span length, including 0
for both empty plaintext and bad padding. The HKDF return is its output length,
and the DH padded-public export return is its output length. Other rows record
the upstream success/failure result. Inputs and private keys here are public
test values and must never be used as production credentials.

Rows with intentional Rust differences carry both outcomes in the output
column. Every DH peer row has `upstream=<secret>;rust=accept|reject;rust_secret=<secret>`;
the upstream return is in column four. Rust's accepted secrets are calculated
independently with OpenSSL BN modular exponentiation, including `p - 8` even
if the provider rejects `p - 2`. Rejected or failed outcomes have `-` for the
corresponding secret. The separate `public-padded-8` row is a public-key
export, not a peer result. CBC rows include `span=<upstream returned bytes>`,
`rust=accept|reject`, and `rust_plain=<plaintext or ->`; valid rows also
record `encrypt` and `cipher`. The 8191- and 8192-byte 802.11 KDF rows use
`upstream=<bytes>;rust=accept|reject`. SPKI rows use
`upstream=<DER>;rust=accept|unsupported-curve`; the two unsupported curves are
P-192 and P-224. The other byte outputs remain plain hex unless the row has
named fields for multiple values.

Two defects are retained in the verbatim pinned upstream code: the AES-SIV
variadic functions do not call `va_end`, and `compute_ec_ss_x` leaks its
temporary `EC_POINT`. The harness supplies the exact `char *` variadic argument
types and releases its own objects, but cannot repair those upstream bodies
without changing the oracle. The ECDH leak is limited to three calls per
fixture process and ends when that process exits.
